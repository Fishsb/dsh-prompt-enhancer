# v3.0.0 — 模式体系重构 + 一键发布升级（大版本）

> 发布日期：2026-08-16 · 这是从 v2.8.3 起的**大版本升级**：检索体系全面重构、一键发布升级为「多步网络检索 + 生成提示词规格」、超时体系按真实耗时校准。

## ✨ 模式体系重构（v3.0）

5 种模式全部重定义，检索从「规则 + 全量」升级为「LLM 判定 + 分级窗口」：

| 模式 | 行为 |
|---|---|
| **基础** | 直发优化，不读取任何上下文（不变） |
| **轻量** | 参考最近 1 轮会话——LLM 判定关联性，有关联才注入参考 |
| **标准** | 递进窗口检索（最近 1-2 轮 → 3-5 轮 → 6-10 轮），每窗口 LLM 判定，命中即停 |
| **智能** | 会话窗口检索 → **开发意向判定**（非开发意向直接停）→ 工作区 .md 文档分析（含项目地图结构）→ 代码文档参考（按项目地图路径优先）→ 专业词汇优化 + 调整方案 |
| **一键发布** | 见下方「一键发布 v3.0」 |

- 会话参考注入保留防回显护栏；LLM 判定 10s 超时/失败自动降级（不阻断主流程）
- 新增提示词事实源：relevance / intent / doc-analysis / smart / websearch

## 🚀 一键发布 v3.0（publish 多步检索 + 产物形态调整）

- **多步网络检索**：LLM 自动规划 2~3 个差异化检索主题（避开已检索主题）→ 逐主题搜索 → 结果按主题合并注入【网络参考】（≤1600 字符）
- **跨轮检索记忆**：已检索主题 + 要点摘要会话级记忆（≤600 字符），下一轮以【已获取网络参考】回注，只补新缺口、不重复检索；搜索失败的主题不占位可重试
- **产物形态**：九章规格重写为「**完善、有明确边界的生成提示词**」——场景化角色设定（游戏开发专家/软件架构师）、需求范围与硬边界（绝对/必须/不得）、技术约束与架构（写实到方案名：渲染管线/合批/后处理/材质体系）、核心要求逐条附设计意图、交付与限制（禁止 TODO/占位）、逐条验收清单
- 保留：场景自动路由（游戏/软件/通用）、网络信息运用（标注来源、不得虚构）、方案自评判定（【保留】/【调整】闭环）、多轮完整九章扩充、记忆强制开启、不设输出限制（240s 超时）

## ⏱️ 超时体系按真实耗时校准（实测驱动）

- 真实 LLM 实测：长草稿 + 深度思考完整生成 42s > 默认 30s → **链含思考等级（reasoningEffort）时主调用超时自动放宽 ≥120s**
- 判定/规划类小调用剥离思考等级（5 处），消除「思考消耗小预算 → 空流」风险，10s 超时余量充足（实测 2s 级）
- 会话历史/事件检索补 10s 超时保护（超时降级不阻断）

## 🧹 稳定性与治理

- publish 多步检索审查修复（memo 截断方向、失败主题不入记忆、主题硬去重、预算门前置）
- 文档架构与发布边界规则：功能文档与开发治理文档分开存放，发布物仅含功能文档 + 运行代码（13 文件白名单）
