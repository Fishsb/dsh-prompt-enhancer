# v3.4.2 — Windows 平台修复版（宿主启动约 5 秒被自己的 worker 清扫杀掉）

> 本版主线是**一处只在 Windows 上成立、且会把宿主进程直接杀掉的缺陷**：插件启动 5 秒后自动执行的 worker 清理逻辑，在 Windows 上会把本机**全部** node 进程（含宿主自身）当成待回收的 worker，随后把发现集里除「保留者」以外的进程逐一 `process.kill()` —— **宿主把自己杀掉了**。
> 本版**无破坏性变更**，配置与既有功能无需迁移。

## 🐛 修复

- **Windows 上宿主启动约 5 秒后静默退出，界面永久停在「自动重连中」**：现象是 Windows 上宿主启动后约 5 秒**静默退出**——stdout / stderr 无任何读数、无栈、无 `fatal load failure`；前端页面已渲染（主题、宠物、通知桥均正常），但连接永不成代，用户侧表现为"服务起不来"。

  根因是 `workerPidsByProcessScan()` 两条平台分支的**判据不一致**：

  | 平台 | 判据 | 结果 |
  |---|---|---|
  | posix | 遍历 `/proc/<pid>/cmdline`，只认「某参数等于 worker 脚本路径或以 `<sep>asr-worker.cjs` 结尾」 | 正确 |
  | **win32** | **只按进程名** `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 枚举 | **返回本机全部 node 进程** |

  这与该函数的自述判据（「命令行里出现本插件的 `asr-worker.cjs` 路径」）相悖。后果不是「少发现」而是「全都发现」：清理函数 `sweepStaleWorkers()`（挂在 `ensureWorker()` **入口最前**、无条件执行）按「只留一个」把发现集其余项逐一 `process.kill()` ⇒ **宿主把自己杀掉**。

  该 win32 分支自 `8abe49c` 引入起**从未被执行**（开发机为 Linux；上游 CI 只跑 `ubuntu-latest`；既有回归用例全用 `pgrep` / `/proc` / 硬编码路径，Windows 上跑不了）。

  本版按最小改动修复三处：① win32 分支补上命令行过滤（`$_.CommandLine -like '*asr-worker.cjs*'`），与 posix 分支同源；② 枚举结果排除 `process.pid`；③ 清理循环增加 `pid === process.pid` 跳过（纵深防御：发现面将来再退化也不得自杀）。未改 posix 分支、未改保留者挑选策略、未改 worker 启停语义、未引入新依赖。

## ✅ 本修复的实测方式

- **Windows 侧真实环境实测**（本机 win32，真进程非夹具）：改前 `workerPidsByProcessScan()` 把本机当时的 node 进程**全部**入列（含调用者自身），改后返回空集；`process.kill` 拦截实测到宿主对**自身 pid** 发出 kill（改前），改后零 kill；端到端复现「调用 `ensureWorker()` 后进程静默死亡」（改前）与「进程存活、正常返回」（改后）。
- **新增回归判据** `test/asr-worker-reap-win32.test.cjs`（3 条，已登记进 `npm test` 列表）：结构腿（win32 必须按命令行过滤 + 清理必须跳过自身）+ 反向行为腿（扫描不得返回非 worker 进程，含自身）+ 正向行为腿（命令行携带 worker 脚本路径的进程必须被发现，防「改成 `return []`」这类假修复）。**有牙实测**：把修复还原为改前版本后，结构腿与反向行为腿在真实 Windows 上报红。
- **CI 读数**（`ubuntu-latest`）：job `test` 全绿，23 个测试文件 / 307 项 / 306 通过 / 0 失败。
- **边界（如实声明）**：上游 CI 只跑 `ubuntu-latest`，**win32 分支在 CI 上不被执行**；上述 win32 读数均为本机实测（非 CI 覆盖），结构腿即为 CI 上可见的对应信号。

