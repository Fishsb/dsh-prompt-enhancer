# 🧠 v2.7.0 · 发送前多轮迭代 + 一键更新链路修复 + 更新未重启提醒（合并版）

> 本版合并 v2.7.0 及其后的全部迭代：记忆链、继续优化按钮、执行器一键更新链路四修复、环境检测真实依赖化、更新未重启提醒。

## 更新未重启提醒（新增）
- `dsh plugin add/update` 安装新版本后若**服务未重启**，插件管理页自动显示横幅：「⚠️ 检测到插件文件已更新，但服务尚未重启——重启后新版本生效」+ 重启命令（`net stop dsh-web && net start dsh-web`，服务名随 `updater.serviceName` 配置）
- 检测原理：host 对比「本进程模块加载时刻」与磁盘关键文件 mtime——安装更新后文件变新 → 命中提醒；重启后消失

## 记忆升级：多轮迭代链（记忆开关开启时）
- **之前**：只记住上一轮优化结果，再优化时只参考一对「输入/输出」
- **现在**：发送前「优化 → 修改 → 再优化」的每一轮改动都会累积（最多最近 4 轮输入/输出），再优化时以**真多轮 user/assistant 对话消息**代入全部轮次，让模型理解你的意图演化
- **修改方向感知**：通过行级 diff 自动识别你相对上一轮结果的调整（`+新增 / -删除` 摘要 ≤300 字符）
- **预算规则**：记忆链 ≤2400 字符按轮等分（输入 1/3、输出 2/3）；撤回只弹出最后一轮

## 按钮「继续优化」状态
- 首次优化完成后继续修改草稿 → 按钮变为**纯文字「继续优化」**（无 ✨ 图标）；撤回 = 回到起点恢复首次形态；其余状态不变

## 一键更新链路修复（v2.6.0 四个断点全部闭环）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | **CORS 头缺失** | 浏览器预检失败 → 「更新执行器不可用」 | 补 `allow-methods` + `allow-headers`（浏览器模拟预检实测通过） |
| 2 | **`DSH_DSH_BIN` 从未注入** | 安装必然 BAD_ARGS 失败 | spawnExecutor 从 `process.argv[1]` 注入 dsh CLI 入口 |

| 4 | **执行器版本不递增** | 修复代码不上线 | `EXECUTOR_VERSION 0.1.0 → 0.1.2` 触发版本对齐重建 |

## 环境检测真实依赖化

```
环境检测（5 项）
├─ 服务状态        block — 服务存在（sc stop/start 前提）
├─ 服务启用状态    block — 未禁用（sc start 前提）
├─ 服务可执行文件  block — nssm Application / 原生 ImagePath 降级链（覆盖未装 nssm 形态）
├─ 重启工具        block — sc/netstat/reg 可用（重启命令与健康检查前提）
└─ 更新端口独立    warn  — ≠ 服务端口、未被无关进程占用、端口解析正常
```

- **svc-bin 降级链**：nssm `Parameters\Application` → 未装 nssm 的原生服务读 SCM `ImagePath` 首段 → 均无则跳过
- **新增 tools**：sc/netstat/reg 存在于 `SystemRoot\System32`
- 删除标准场景不可达的 port 占用检查、与重启无关的 account/restart；显示名统一用户口径「更新端口独立」
