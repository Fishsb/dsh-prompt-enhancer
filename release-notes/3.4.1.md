# v3.4.1 — 兼容性修复版（DSH 0.2.x 上 ✨ / 🎤 与设置页恢复）

> 本版主线是**一处让插件在新版 DSH 上被整体拒绝装载的问题**：DSH 升到 `0.2.0` 及以后，插件在 profile 启动阶段被宿主的兼容性门直接跳过，✨、🎤 与设置页卡片全部消失（且界面无任何提示）。已在市场版本（v3.4.0）上复现并被用户报告（Issue #11 / #12）。
> 本版**无破坏性变更**，配置与既有功能无需迁移。

## 🐛 修复

- **插件在 DSH `0.2.0`+ 上被拒绝装载，✨ / 🎤 / 设置页全部不出现**（Issue #11 / #12）：根因有两条，叠加才致功能整体消失——
  1. `@deepseek-ai/dsh-client-runtime` **自 DSH `0.2.0` 起已从官方发行物中移除**，而插件仍把它声明为依赖（同时写在 `peerDependencies` 与客户端注入表里）。这是一个**历史遗留声明**：插件代码从未真正使用过它（客户端产物里对它的引用为 0 次，唯一的运行期依赖是 React）。
  2. 语言包 `@deepseek-ai/dsh-client-locale` 的版本范围写成了 `^0.1.0-rc.6`。语义化版本里 `^` 前缀在 `0.x` 上**只允许同一小版本**（即 0.1.x），因此对 `0.2.x` 一律判定为「不满足」。

  两条叠加后，宿主在**启动时**就把整个插件判为不兼容并跳过——所以你看到的是「插件装在那里，但什么都点不出来」，而不是一条错误提示。本版按官方处置：**移除已不存在的依赖声明**（而非放宽它的版本），并把语言包范围改为 `>=0.1.0-rc.6`，**同时覆盖 0.1.x 与 0.2.x 两代宿主**。

  > 升级后无需任何手工操作：装上新版重启 DSH 即可。若你此前安装的是 v3.4.0，重启后那行 `skipping profile bundle "dsh-prompt-enhancer"` 警告会消失。

## 🛡️ 稳定性与平台修复（自 v3.4.0 起累计）

- **本地语音引擎的 worker 进程泄漏（Linux / WSL 通道，问题严重）**：语音识别在 Linux 上启动本地引擎时，有一处进程发现逻辑只在 Windows 成立——它无条件调用 `netstat` 且只认 `LISTENING` 字样，而 Linux 上该命令往往不存在、输出也是 `LISTEN`。结果是「引擎是否已在运行」永远判为「没在运行」，于是**每次启动都新开一个约 420MB 的识别进程，且全链路没有任何回收机制**（进程以脱离父子关系的方式启动，卸载插件也不清理）。实测一台机器累积到 **30 个**进程、合计约 **9.6GB**，把内存与交换空间压满，曾导致整机卡死。本版修好了 Linux 侧的进程发现（`ss -ltnp` 主路径 + `netstat -tlnp` 退路），并补上两道防护：**进程扫描发现面**（不再依赖「最多只能看到两个进程」的端口文件）与**启动时清扫**（枚举全部识别进程，只保留正在服务的那一个）。内存占用自此稳定。
- **同一处泄漏的连带修复**：因上述「永远判为没在运行」，每次启动都会重复拉起新进程。发现面与清扫就位后，重复拉起同时消除；启动路径的清扫挂在入口最前，即使模型未安装也会先收敛残留进程。

> 说明：本版 CHANGELOG 中另有若干条 2026-09-26/27 的**门禁与文档治理**条目（gate 环状态出口、退出码三态、投影漂移归因等），属仓库内部工程质量工作，不影响插件在 DSH 中的行为，故不在本发布说明中展开。

## 📦 安装

```sh
dsh plugin --profile web add github:Fishsb/dsh-prompt-enhancer#v3.4.1
```

升级已有安装：

```sh
dsh plugin --profile web update dsh-prompt-enhancer
```

> ⚠️ 插件在本机运行环境里生效需要**重启 DSH**（host 半部变更）；浏览器端刷新页面即可加载新的客户端半部。
