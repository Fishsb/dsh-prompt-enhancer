# 方案：「一键发布」场景路由与方案自评（v2.2 · 三轮审查修订版 · 已实施）

> 本方案汇总 2026-08-15 协商会话中「一键发布（publish）」模式从需求、设计、实测到修正的全部结论，
> 明确每项调整的依据（实测驱动）、具体改进点与剩余实施步骤。**状态：已按 v2.2 实施并完成真实 LLM 复测（2026-08-15），
> 复测中发现并修复 4 项实现层缺陷（见「八、实施与实测记录」）。**
>
> **v2 修订（一轮审查）**：① 自评段红线豁免条款（R1）；② 多轮场景判定固定规则（R2）；③ 词表分级加权 + 英文强词（R3/R4）；
> ④ 生效条件拆分表述（R5）；⑤ 实施步骤补地图 sync；⑥ 验收清单量化（测试输入 ↔ 期望映射表）；⑦ 回退粒度单点化；
> ⑧ scenario 随 context 返回值带出（实现细节）。
>
> **v2.1 修订（二轮逻辑审查）**：L1 「首轮判定固定」补承载机制——会话级缓存（首轮判定缓存、后续轮读取，不重判）；
> L2 判定移至 enhance 入口（与预算解耦，「路由始终生效」成立），scenario 改为**传入** buildV2ContextBlock（供检索后缀），
> 日志独立行；L3 验收 ④ 改多离散需求输入 + 放宽断言（三轮内 ≥1 次【调整】）；L4 publish.md L6 软适配句并入新「场景适配」段（单一事实源）。
>
> **v2.2 修订（三轮逻辑审查）**：D1 验收表补**会话隔离**（①/②/④ 与缓存互斥，② 同会话必失败）；D2 重启兜底——缓存 miss 且
> memRounds 非空时用 **memRounds[0].input** 判定（重启续作不翻转），判定源与注入轮次同源；D3 缓存写入时机明确为「system 注入前、
> 与 LLM 成败无关」；D4 自评「输出格式」行删除（与四节结构歧义）；D5 单测 keywords 缺省断言改等价断言（`undefined` ≡ `[]`）。

## 一、背景与目标

**需求**：新增「一键发布」模式——输入粗略想法（如「我想开发一个纸牌游戏」），一键生成完整可实施的开发规格（目标/数据结构/核心机制/交互/技术方案/实施路线/验收清单），多轮补充可逐步细化。

**目标形态**：模糊想法 → 场景自动路由（首轮判定、会话级缓存固定：游戏/软件/通用）→ 九章规格生成（网络检索 + 工作区参考）→ **方案自评判定**（保留/调整）→ 多轮扩充闭环。

## 四、待实施改进点

### 改进点 1：场景自动路由（方案 C · v2.2 修订版）

1. **`detectScenario(text, keywords?)` 纯函数**（PURE 区段，可单测；keywords 可选，缺省按 text 判定）——**词表分级加权（R3）**：
   - **强特征词 ×2**：卡牌 / 塔防 / 肉鸽 / roguelike / Boss / 副本 / 抽卡 / 回合 / 射击 / 放置 / 解谜 / 成就 / 装备 / 技能 / 关卡 / 战斗（游戏侧）；API / 数据库 / 微服务 / 后端 / 前端 / 权限 / 登录 / 部署 / 中间件 / 缓存 / 并发（软件侧）
   - **泛词 ×1**：游戏 / 玩法 / 角色 / 剧情 / 地图 / 等级（游戏侧）；软件 / 应用 / 系统 / 平台 / SaaS / Web / 网站 / 工具 / 管理 / 协作 / 自动化 / 脚本 / 插件 / 客户端 / App / 移动端 / 桌面（软件侧）
   - **英文强词 ×1（R4）**：game / card / roguelike / level / battle / boss（游戏侧）；app / website / web / api / database / dashboard / crm（软件侧）；**匹配前统一小写**
   - 计分制：加权求和、多者胜；**平局 / 双零 → generic**；返回 `game | software | generic`
2. **多轮场景规则（v2.1：L1 补承载机制；v2.2：D2 补重启兜底、D3 明确写入时机）**：
   - **会话级缓存固定**：会话内**首次 publish 调用**判定并写入缓存（`Map<sessionId, scenario>`，生命周期 = 插件进程/会话）；后续轮次一律读取缓存，**不重判**。记忆链开关与此无关（记忆链关时的手动多轮同样固定）。理由：场景决定九章骨架，翻转会推翻已确认设计（多轮红线）；「首轮=无记忆链轮次」判据因记忆链开关/跨模式共享不可靠，故以会话内首次调用为准。
   - **判定源规则（v2.2：D2）**：缓存 miss 时——`memRounds` 非空 → 用 **`memRounds[0].input`**（时间窗 `MEMORY_ROUNDS_MAX=4` 内最早轮输入，最接近原始想法）判定；无 rounds → 用当轮 text。覆盖「进程重启后续作」主场景：重启清缓存后 rounds 属同一 publish 项目 → 判定正确、不翻转；且判定源与注入轮次同源，引导与模型视角一致。
   - **写入时机（v2.2：D3）**：判定 + 写入在 system 注入前完成，**与 LLM 调用成败无关**（scenario 仅依赖 text，失败重试不改变结果；同会话重试不同想法属已知边界）。
3. **system 场景引导**：判定结果显式注入 system——「本次场景判定：game/software」+ 场景适配指令（文案内置 publish.md「场景适配」段为事实源）：
   - game：三、数值与经济按数值表/经济公式展开；五、核心机制含玩法系统
   - software：三、数值与经济改性能指标与容量约束；五、核心机制改核心功能与业务规则；补充数据流与 API 设计
   - generic：默认九章（不追加）
4. **检索词场景化**：`buildWebQuery` 结果追加场景词（game → 游戏实现；software → 软件架构；generic 不追加）
5. **生效条件（v2.1：L2 修正）**：
   - 场景路由 + system 注入：**publish 模式始终生效**——判定在 enhance 入口执行（text 同作用域，与预算无关），不再依赖 buildV2ContextBlock 调用
   - 检索词场景后缀：**publish + 预算>0**（检索路径内）
6. **日志（v2.1：L2 修正）**：`scenario=game/software/generic` **独立 hlog 行**（enhance 入口），不并入 web 日志（web 日志仅在预算>0 时存在，预算=0 会丢日志）
7. **实现细节（v2.1：L1/L2 修正，方向反转）**：判定在 **enhance 入口**完成（publish 分支，缓存读写，判定源见第 2 条），scenario 作为参数**传入** `buildV2ContextBlock`（供检索词后缀）；buildV2ContextBlock **不再负责判定/带出**。单点计算、无两处漂移、与预算解耦
8. **回退（单点化）**：移除 enhance 入口 publish 分支三处接线（缓存读取 + system 注入 + 传参）即回退；`detectScenario` 纯函数与缓存 Map 保留不接线无害，不影响其他模式

### 改进点 2：方案自评判定（优化侧模型自执行 · v2.2 修订版）

publish.md 追加【方案自评判定】段（第十部分附录，不改变九章框架）：

```
【方案自评判定】（输出规格后必须追加，不改变九章框架；以【方案自评】开头，按以下一~四逐项输出，v2.2：D4）
一、一致性核对：用户已明确需求逐条是否都有章节覆盖？缺项列出。
二、完整性核对：九章是否全部展开？缺章列出。
三、可实施性核对：是否存在未标注「默认」的设计空白？列出。
四、判定结论：【保留】（全部通过，可开工）或【调整】（列出差距项
   + 调整方向，并在「调整建议」小节给出 ≤5 条修订要点）。
锚点规则（防自嗨）：任一「用户明确需求未覆盖」或「九章缺章」→ 必须判【调整】。
【自评段豁免条款】（R1）：自评段不受「不加解释/严禁回显」红线约束——
允许概括引用用户需求点以核对覆盖，禁止逐字回显输入原文；其余正文仍严守红线。
```

- 自评为【调整】→ 调整方向供用户下一轮补充（记忆链）→ 再自评 → 闭环
- **跨轮衔接**：自评块随 output 存入记忆链 rounds，但**不依赖跨轮保留**（记忆链预算截断时输出尾部可被裁剪）；下一轮模型依据用户新草稿判断缺项是否已补
- **无需改动确认**：本改进点不新增配置项 → client 侧（MODE_VALUES / template.texts / i18n / build-client）**无需改动**，实施时不必重复排查

## 六、风险与回退（三轮审查修订版）

| 风险 | 应对 |
|---|---|
| 词表误判（"游戏"出现在软件描述） | 分级加权（强特征词 ×2 压过泛词）+ generic 兜底；词表按实测扩充 |
| 多轮场景翻转（增量文本命中另一场景词） | **会话级缓存固定**（首轮判定缓存、后续轮读取不重判）；进程重启后缓存 miss → **memRounds[0].input 兜底判定**（主场景正确，v2.2：D2） |

| 同一会话中途换新项目（场景应变） | 缓存固定语义下场景不自动切换；用户新起会话即重新判定（已知边界，记录不修复） |
| LLM 自评流于形式（自嗨） | 锚点规则强制（缺需求/缺章必须判【调整】）；实测构造多需求输入验证 |

| 自评段增加输出长度 | publish 已不设输出限制 ✅；记忆链预算截断时自评块尾部可裁剪（不依赖跨轮保留） |
| 路由/自评行为异常 | 改动集中在 publish 路径；回退=移除入口三处接线（缓存读取 + system 注入 + 传参），纯函数保留无害，不影响 base/lite/standard/smart |

### 真实 LLM 三场景复测（测试输入 ↔ 期望断言；**会话隔离要求 v2.2：D1**）
