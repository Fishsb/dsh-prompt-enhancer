# 项目地图 · 说明与维护（docs/map）

> 本目录是 dsh-prompt-enhancer 的**项目地图**，与代码构成「同一事实的两面」。
> 地图过期 = 代码隐患。任何结构性改动后，必须回来更新地图。

## 这是什么

一套给 AI agent（Cursor / Claude Code / Codex）「按地图改代码」的分层索引：

- **root** — 模块级视图（区域→职责→影响谁）
- **tree** — 文件级索引（文件→职责→影响→关联 FLOW）
- **flow** — 功能链路（用户动作→代码→接口→数据→影响的完整因果链）

## 为什么用地图

| 不用的痛 | 用了之后 |
|---|---|
| AI 全项目扫描，浪费上下文 | 按地图定位，省 token、少误伤 |
| AI 不知道该改哪个文件 | 地图直接告诉它 |
| 不知道改了影响谁 | 链路图把「牵一发动全身」画出来 |
| 项目越改越乱、几月后集体失忆 | 地图+日志对抗「项目失忆」 |

## 地图维护规则（半自动）

- **每次改完代码，同步更新地图**：文件增删/移动 → `tree/`；模块职责 → `root.md`；功能/入口/API/行为 → `flow/`。
- **新增功能链路** → 新建 `flow/<name>.md` + 在 `index.md` 登记 FLOW-ID。
- **地图与 CHANGELOG 交叉引用**：日志条目标注涉及 map/flow-id。
- 详细规则见 `../AGENTS.md` 第「二/三」节。

## 命名约定

- 地图文件用 `kebab-case`（如 `version-update.md`）。
- 功能链路统一加 **FLOW-ID 前缀**：`PEN-`（增强）、`VU-`（版本更新）、`DG-`（诊断）。
